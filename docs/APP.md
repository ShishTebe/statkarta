# Приложение: устройство

Разделы ниже описывают Фазы 1 и 1.5; что добавилось в Фазах 1.6 – 3 – последний раздел.

## Сборки

| Файл | Данные | Назначение |
|---|---|---|
| `dist/statkarta-offline.html` | публичные пакеты (без справочника № 17) | распространение, GitHub Releases |
| `dist-private/statkarta-offline-local.html` | плюс справочник № 17 | только для рабочего компьютера заказчика, не публикуется |

Файл открывается двойным щелчком в любом современном браузере, установки не требует.
Внешних ресурсов нет; политика безопасности содержимого в самом файле запрещает любые
сетевые запросы (`default-src 'none'`).

Фреймворк и внешние пакеты не используются: сборка и тесты работают на Node 20+ без установки
зависимостей из сети.

## Дело (схема `case/2`, с версии 0.3.0)

Дело содержит объекты учета (эпизоды, лица, потерпевшие), сведения об ущербе, события и
карточки событий. У факта хранятся версии по событиям: карточка берет значение, действующее
на дату своего события. Карточка, отмеченная «выставлена», хранит снимок памятки и больше не
меняется; при расхождении программа предлагает карточку в режиме «изменить».

Файл дела прежней версии (`case/1` – формат Фазы 1) открывается с миграцией: ответы
раскладываются по областям, формы становятся карточками события «Перенесено из версии 0.2».

Профиль органа: наименование и код органа, код подразделения и код органа прокуратуры (справочник № 17),
подписи (должность, звание, фамилия) следователя, руководителя и прокурора, перечень карточек, где нужны
код и подпись прокурора, формат номера дела, срок хранения. Что куда подставляется, задано в пакете
событий (`profile_facts`, `profile_fills`, `profile_signatures`), а не в коде: у правила может быть
`forms_from` – имя списка форм в профиле.

Сведения дела живут в памяти вкладки. На устройство они попадают только зашифрованными:
AES-GCM, ключ из пароля через PBKDF2-SHA-256 (310 000 итераций); в записи открыто хранятся
только служебные даты удаления и напоминания. Кнопка «Удалить данные дела» стирает и
сохраненную копию. Профиль органа хранится отдельно (localStorage) и сведений дела не содержит.

## Пакет карточек по событию

1. Событие выбирается из `data/events/<год>/events.json`, у него дата, признаки и ссылки на объекты.
2. Программа порождает состав пакета; карточку можно убрать или добавить вручную – пометка сохраняется.
3. Опросник пакета объединяет вопросы всех карточек без повторов и показывает, какие реквизиты
   каких карточек закрывает ответ.
4. Значения, общие для нескольких карточек, переносятся: в памятке указано «перенос из ф. N, реквизит M».
5. Межкарточные соотношения (`scope: package`) проверяются по составу пакета.
6. Бланки всех карточек события скачиваются одним архивом или печатаются копиями за один проход (с версии 0.7.0 печать памяток снята).

## Логика памятки (проекция карточки)

Памятка – внутренняя проекция карточки: строки реквизитов со статусом и источником. На экране она
показывается таблицей реквизитов на вкладке «Печать бланка» (с версии 0.7.0), отдельно не печатается.

1. Общие сведения (квалификация, даты, номера, повод) задаются первыми.
2. Из квалификации и даты преступления ядро выводит умолчания: категорию по перечням № 4–7
   на дату преступления, стадию по ст. 30 УК РФ, подсказки о направленности по перечням № 2 и № 23.
3. Для выбранной формы задаются вопросы только по реквизитам, которые заполняет следователь
   или начальник органа; общий ответ переиспользуется в других формах.
4. Памятка перечисляет все реквизиты формы в порядке бланка со статусом и источником значения.
5. Контрольные соотношения из `data/rules/<год>/checks.json` выводятся над памяткой.

Статусы: «Заполнить» (ответ), «Умолчание – проверьте», «Подсказка – проверьте», «Не заполнять»,
«Уточнить», «Нет данных», «Заполняет ИЦ», «Заполняет работник регистрационного учета», «Заполняет суд».

## Печать

Печатается только печатная копия бланка (`blankSheet`): состав и порядок реквизитов бланка,
клетки кодов, строки подписи по профилю органа; карточки с ошибками контроля не печатаются, а
перечисляются на листе «Проверьте перед подписью». Печать памяток снята в версии 0.7.0.

Вымышленные примеры для проверки: `#demo-package` (дело с двумя эпизодами и двумя лицами,
пакет события «Направление в суд», вкладка «Печать бланка»), `#demo-blanks-print` (печать копий
бланков события), `#demo-full-print-<форма>` (ответ на каждый вопрос – худший случай для печати
копии бланка).

```bash
node scripts/build-app.mjs
```

```bash
node --test tests/phase1.test.mjs
```

## Ввод кодов (с версии 0.2.0)

| Режим | Когда | Как работает |
|---|---|---|
| Один код | в бланке одно поле, коды – порядковая нумерация | новый выбор заменяет прежний |
| Несколько кодов | в бланке несколько кодовых полей | не больше числа полей, лишнее не выбирается |
| Наложение | коды позиционные: справочники № 2, 3, 4, 9, 10, 14 и встроенные коды вида 1000, 0100 | коды разных разрядов складываются (2000 + 0030 = 2030), код того же разряда заблокирован с объяснением |

Число полей определено по векторным ячейкам официального бланка (`scripts/import/blank_cells.py`),
исключения записаны в `scripts/import/form-corrections-2026.json` со ссылкой на бланк.

Подсказки кодов (`data/rules/2026/hints.json`) предлагают коды, но не проставляют их. Условия
неактивности вопросов – `data/rules/2026/availability.json`.

ОКАТО: положите официальный CSV Росстата в «Карточки/ОКАТО/» и запустите

```bash
python3 scripts/import/import_okato.py --regions 30
```

Без параметра `--regions` импортируются все регионы (файл сборки заметно вырастет).

## Экран запуска, быстрый режим и печать бланка (0.7.0)

- **Экран «Дела»** (`startView`): две кнопки – «Быстрый режим: одна карточка» и «Создать дело»
  (по нажатию – выбор «Вручную» или «Из файла»; один выбор файла принимает и документ, и
  сохраненный файл дела). Ниже – открытые дела сеанса (`state.cases`, все дела в памяти вкладки,
  текущее – `state.kase`) и сохраненные на устройстве (в записи открыто хранятся `label` –
  обозначение дела и `saved_at`). Несохраненные изменения и пароли учитываются по делу
  (`state.dirtyIds`, `state.passwords`), новое дело не требует закрывать старое.
- **Быстрый режим** (`quickView`): дело с признаком `quick` живет только в памяти и в список дел
  не попадает; событие `ev.manual`, одна карточка по выбранной форме (объекты учета по
  кратности формы – `QUICK_OF`), опросник только по ней в порядке бланка, внизу – проверка,
  заполненный файл и печать копии; отметки «выставлена» нет.
- **Вкладка «Печать бланка»** (`printView`, `cardPanel`, `reqTable`) заменила «Памятки пакета»:
  список карточек события, для выбранной – все реквизиты в порядке бланка со значением, статусом
  и источником, правка на месте (вопрос опросника раскрывается под строкой), ошибки бланка с
  переходом к строке, отметка «выставлена», скачивание бланка и печать копии; по выставленной –
  «Корректирующая карточка» (режим «изменить») и «Отменяющая карточка» (режим «снять», если у
  формы есть такой код: `modeRequisite`, `createChangeCard(c, evId, baseKey, mode)`).
  Печать памяток и копирование текстом сняты.
- **0.7.1.** В быстром режиме есть блок документа (`documentView({ quick: true })` →
  `quickImport` → `rebindQuickCard` в ядре) и кнопка «Перенести в дело» (`quickToCase`: снимается
  признак `quick`, дело попадает в список открытых).
