# Язык правил

Правила – декларативный JSON, исполняемый ядром приложения без языковых моделей.

## Ссылки

| Запись | Значение |
|---|---|
| `fact.<сущность>.<имя>` | Факт дела из словаря `data/rules/<год>/facts.json` |
| `req.<номер>` | Значение реквизита текущей формы |
| `req.*` | Каждый реквизит формы, к которому применяется правило |
| `gp-razj-2025-07#NNN` | Абзац разъяснений из `data/legal/<год>/explanations.json` |
| `event.date`, `event.<признак>` | Дата и признаки события дела (правила `data/events/<год>/events.json`, проверки пакета) |
| `attr.object.<признак>`, `attr.damage.<признак>` | Признак экземпляра объекта или ущерба (`object_attrs` пакета событий) |

## Операторы условий (`when`, `assert`)

| Оператор | Истинно, если |
|---|---|
| `{"exists": ref}` | значение задано и не пустое |
| `{"empty": ref}` | значение не задано |
| `{"eq": [a, b]}` | значения равны |
| `{"gt"/"gte"/"lt"/"lte": [a, b]}` | сравнение чисел или дат ISO |
| `{"matches": [ref, regex]}` | строка соответствует шаблону |
| `{"any_in": [ref, [коды]]}` | хотя бы один выбранный код из списка |
| `{"all": [...]}`, `{"any": [...]}` | логические И, ИЛИ |
| `{"fills_by": "ic"}` | реквизит заполняет указанный участник |
| `{"field_type": "enum"}` | реквизит указанного типа |
| `{"fn": имя, "args": [...]}` | вызов функции ядра |

## Функции ядра

| Функция | Результат |
|---|---|
| `uk.category(qualification)` | категория по пакету УК на дату преступления: `small`, `medium`, `grave`, `especially_grave` |
| `uk.category_code(qualification)` | код категории для реквизита карточки: 2, 3, 1, 4 |
| `uk.stage(qualification)` | 1 при ч. 1 ст. 30, 2 при ч. 3 ст. 30 УК РФ, иначе пусто |
| `uk.in_list(qualification, N)` | входит ли статья в перечень № N с учетом условий по дате |
| `uk.article_in(qualification, [статьи])` | квалификация содержит одну из статей |
| `uk.article_in_note(qualification, noteId)` | статья упомянута в абзаце разъяснений |
| `classifier.has_code(value)` | код есть в справочнике реквизита действующей редакции |
| `form.has_option(value)` | код есть среди вариантов реквизита в бланке |
| `case.has_form(N)` | по делу строится карточка формы N |
| `case.had_card(форма, вариант)` | карточка формы (варианта) по этому эпизоду выставлялась на более раннем событии |
| `package.has_form(форма)` | карточка формы есть в пакете события |
| `package.count_cards([формы])` | число карточек этих форм в области проверки (по эпизоду или по всему пакету) |
| `package.count_cards_case([формы])` | то же по всем событиям дела |
| `package.count_objects("persons"\|"victims")` | число лиц или потерпевших события, связанных с эпизодом |
| `package.req(форма, реквизит)` | значение реквизита карточки этой формы в пакете |

## Область действия правил (с версии 0.3.0)

| Поле | Где | Значения |
|---|---|---|
| `scope` у факта (`facts.json`) и сопоставления (`mapping.json`) | откуда берется значение | `case`, `crime`, `person`, `victim`, `card` |
| `scope` у проверки (`checks.json`) | что проверяется | `card` – одна карточка (как в Фазе 1), `package` – пакет события |
| `per` у проверки пакета | как обходится пакет | `case` – один раз, `crime` – по каждому эпизоду события |

Карточка получает значение факта по области: `case` – сведения дела, `crime` – эпизод карточки
(для карточки на лицо – эпизоды этого лица), `person` и `victim` – экземпляр лица или потерпевшего,
`card` – сведения самой карточки. Значение берется на дату события карточки (версии фактов).

## Пакет событий (`data/events/<год>/events.json`)

Событие: `id`, `title`, `final` (признак или условие), `refs` (какие объекты указываются),
`attrs` (признаки события: основание приостановления, вид прекращения, номер дела),
`sets_facts` (какие факты задает само событие), `cards` (правила состава пакета),
`optional_cards` (карточки по обстоятельствам – добавляются вручную), `action: spawn_case`
(выделение дела). У правила карточки: `form`, `variant`, `per`, `when`, `note`, `source_note`.

Кратность `per`: `case`, `crime`, `person`, `victim`, `person_crime` (пара «лицо – эпизод»),
`crime_without_person` (эпизод без установленного лица), `foreign_participant` (иностранный
участник – лицо или потерпевший).

`transfer_priority` задает порядок первичности карточек при переносах, `mode_codes` – коды
реквизита «Учесть, изменить, снять» для режима карточки.

## Шаблоны извлечения

Шаблоны в `extract.json` пишутся в синтаксисе регулярных выражений Python. В JavaScript
`\w` и `\b` не распознают кириллицу, поэтому ядро переводит их функцией `toJsRegex`
из `scripts/lib-data.mjs` (флаги `imu`). Перед сопоставлением текст документа нормализуется:
буква «ё» заменяется на «е», длинное тире – на среднее, так же как в пакетах данных.

## Статусы значений в памятке

`document` – из документа с цитатой; `answer` – ответ на вопрос; `default` – умолчание, проверить;
`hint` – подсказка; `fills_ic`, `fills_registrar`, `fills_court` – не заполняется следователем;
`unknown` – требует уточнения.

## Перечни статей УК (`data/uk/<год>/lists.json`)

Ссылка перечня: `article`, `parts`, `points`, условие по дате `date` – список условий
вида `{"op": "<", "date": "2024-04-17"}`. По умолчанию условия действуют одновременно (И).
При `"date_mode": "any"` достаточно одного (ИЛИ): так записаны условия «вне диапазона»,
например «30.10.2009>дата>=24.12.2024» – до 30.10.2009 или с 24.12.2024.

Дата сравнивается с датой совершения преступления, а если ее установить нельзя – с датой
выявления (сноска к перечням).

Поле `check` у ссылки:

| Значение | Смысл | Учет в категории |
|---|---|---|
| нет | ссылка верна | учитывается |
| `historical` | статья или часть утратила силу, условие даты в прошлом | только для старых дат |
| `stale_in_source` | в перечне указана часть, которой нет в действующей редакции УК | не учитывается |
| `article_not_found`, `part_not_found`, `date_missing` | дефект распознавания | не учитывается, предупреждение валидатора |

Приоритет при определении категории: ссылка с условием даты и частью, ссылка с условием
даты на всю статью, безусловная ссылка с частью, безусловная ссылка на всю статью.
