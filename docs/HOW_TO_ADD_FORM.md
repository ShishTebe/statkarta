# Как добавить новую форму или новую редакцию формы

Код приложения при этом не меняется (требование FR-23).

1. **Источник.** Положить официальный бланк (PDF с текстовым слоем или .docx) в папку
   «Карточки» рабочего каталога. Проверить гриф и допустимость публикации (риск П-1).
2. **Разбор.** Получить описание реквизитов в формате `data/schema/form.schema.json`:
   номер, наименование, тип (`enum`, `classifier`, `date`, `text`), варианты кодов, номер
   справочника, раздел бланка, кто заполняет (`investigator`, `registrar`, `ic`, `head`, `court`).
   Для редакции 2026 это делает `scripts/import/import_forms.py` из готовой схемы; для новой
   редакции – скопировать скрипт, указать новый источник и год.
3. **Файл.** Записать `data/forms/<год>/forma-<номер>.json` и строку в `index.json` той же папки.
   Старую редакцию не удалять: у нее есть `effective_to`.
4. **Правила.** Запустить `python3 scripts/build_rules.py` (для новой редакции – с путем к ее
   папке). Проверить в `data/rules/<год>/mapping.json`, что каждый реквизит сопоставлен ровно
   один раз; при необходимости дописать проверки в генераторе.
5. **Проверка.** Запустить нормализацию типографики, манифест и валидатор:

```bash
python3 scripts/normalize_typography.py
```

```bash
node scripts/build-manifest.mjs
```

```bash
node scripts/validate-data.mjs --warnings
```

6. **Пакет событий.** Если форма входит в пакет какого-либо события, дописать правило карточки
   в `data/events/<год>/events.json` (`form`, `per`, при необходимости `when` и `variant`) со
   ссылкой на источник и добавить форму в `transfer_priority`. Состав пакетов проверяется тестом
   на эталонном деле `tests/fixtures/case-package.json` – эталон в `tests/golden/package/`.
   Карты ИПК собираются отдельно: `python3 scripts/import/import_ipk.py` (эталонные бланки в
   `data-private/blanks-src/`, нормализация в .docx – нативным Word).
7. **Ревизия.** Предупреждения «наименование требует сверки с бланком» и «повтор кодов
   вариантов» закрыть вручную по бланку.
8. **Выпуск.** Поднять `data_version` в `scripts/build-manifest.mjs`, записать изменения в
   `docs/CHANGELOG.md`.

## Карта раскладки бланка (Фаза 1.6)

Чтобы приложение собирало заполненный файл формы, нужен эталонный бланк и карта раскладки.

1. **Бланк.** Положить файл в `new_cards/` (для .doc и .xls – однократно пересохранить нативными
   Word и Excel, не textutil) и дописать его в список `BLANKS` в `scripts/blanks/normalize.mjs`.
   Если в бланке напечатан образец заполнения, добавить места образца в
   `data-private/blanks-src/scrub-2026.json` – скрипт очистит их и откажет, если фрагмент остался.

```bash
node scripts/blanks/normalize.mjs
```

2. **Разметка.** Скрипт помечает каждое пустое место бланка меткой, печатает размеченную копию в PDF
   нативным Word и по расположению меток определяет, какому реквизиту принадлежит место:

```bash
python3 scripts/blanks/build_layout.py <форма>
```

   Результат – `data/layout/2026/forma-<форма>.json` со статусом `draft`. Место в карте – это
   порядковый номер фигуры в `word/document.xml` (идентификаторы фигур в бланках повторяются),
   поэтому карта действительна только для бланка с той же контрольной суммой.

3. **Сверка.** Замечания разметки печатает проверка; ручные исправления вносятся в
   `scripts/blanks/layout-corrections-2026.json` (по реквизиту целиком) и применяются при повторной
   сборке карты. После сверки с бланком статус карты меняется на `verified`.

```bash
node scripts/check-layout.mjs
```

4. **Контрольное заполнение.** В клетки каждого реквизита вписывается его номер – так видно,
   что значения попадают в свои места:

```bash
node scripts/blanks/testfill.mjs data/layout/2026/forma-<форма>.json /tmp/проверка.docx
```

5. **Проверка на деле.** Заполнение по эталонному делу и сборка файла:

```bash
node scripts/blanks/fill_demo.mjs <форма> /tmp/бланк.docx E1
```

Код приложения при добавлении бланка не меняется: все, что знает программа о бланке, лежит в
`data/blanks/2026` и `data/layout/2026`.

**Если Word просит доступ к файлам.** Word работает в песочнице: при первом обращении к папке он
показывает окно «Предоставить доступ к файлам». Пока окно не закрыто, печать в PDF из скрипта
не выполняется – нужно один раз разрешить доступ к папке `statkarta`.
